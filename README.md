# SignalDesk

A seven-day portfolio and learning project. Day 1 is a local, deterministic conversation-ranking baseline; it needs **zero API keys and zero paid services**. All included conversations are synthetic.

## Run locally

Use Node 22.17.1 or a newer Node 22 release and npm. From this repository root in Git Bash:

```bash
npm ci
npm run dev
```

Open http://localhost:3000. Stop with Ctrl+C. In PowerShell, use `npm.cmd` if execution policy blocks `npm.ps1`; no policy change is required. Dependency installation requires internet access, but the application does not fetch data or fonts from external services. No environment file is needed.

```bash
npm run lint
npm run typecheck
npm test
npm run rank:dev
npm run build
npm start
```

`npm start` serves the completed build. `npm run test:watch` reruns unit tests during development. Run build and typecheck sequentially because both generate Next.js type files.

## Files

- `src/app/`: Next.js App Router page, root HTML layout, metadata, and Tailwind stylesheet.
- `src/components/dashboard.tsx`: brand selector, context, decision filters, and empty/error states.
- `src/components/opportunity-card.tsx`: post metadata, heuristic score, topics, risks, exclusions, and expandable score evidence.
- `src/lib/opportunity-feed.ts`: joins scorer results to their posts and applies a decision filter without changing ranking semantics.
- `src/data/brands.json`: exactly two fictional brands and editable topic aliases/exclusions.
- `src/data/posts.json`: 30 distinct synthetic X-style posts. Empty-input behavior is tested with separate unit examples.
- `src/data/split-manifest.json`: fixed 20-development / 10-held-out assignment by post ID.
- `src/data/human-labels.json`: 60 editable proposed annotations; manually review these before treating them as evaluation targets.
- `src/data/sample.ts`: Zod-validated fixture loader and fixed reference time.
- `src/lib/schemas.ts` and `types.ts`: runtime data contracts and inferred TypeScript types.
- `src/lib/splits.ts`: membership, completeness, and repetitive-family isolation checks.
- `src/lib/ranking.ts`: framework-independent scoring baseline.
- `src/lib/ranking.test.ts`, `src/data/fixtures.test.ts`: rule, schema, and isolation tests.
- `scripts/rank-development.mjs`: runs the existing Vitest development runner and prints all 40 brand/post decisions plus three complete outputs; no extra TypeScript runner is installed.
- Root config files: TypeScript, ESLint, Tailwind/PostCSS, and Vitest.
- `AGENTS.md`: guidance generated by Next.js on development startup.
- `package-lock.json`: exact resolved dependency graph; use `npm ci` to reproduce it.

The Server Component at `/` passes both profiles, only development posts, and the fixed reference time to an interactive Client Component. Select VoiceStack AI or SecureStack to see its context and rankings. The All / Recommend / Review / Skip buttons filter the actual scorer decisions and show computed counts. Sort by **Opportunity priority** (default: Recommend, then Review, then Skip; descending score within each group) or **Raw heuristic score** (descending score regardless of decision). Both modes break ties by post ID and preserve all scoring evidence. The card footer labels the original raw score rank, not its position in the priority-sorted feed. The active filter and sort stay selected when switching companies. Held-out posts are not passed to the dashboard or scored in the UI or development command. Labels are imported only by the fixture contract test, never by the scorer, loader, runner, or page. The held-out set is a repository convention, not an access-controlled secret; keep it out of tuning and routine qualitative inspection.

The dashboard can still be prerendered during the build and is hydrated for brand switching and filtering. Native HTML disclosure controls reveal explanations without additional React state. An empty filter offers a Show all action; an empty dataset shows a separate no-data state. Invalid scoring inputs show a recoverable error, and the Next.js route boundary handles unexpected page errors. See [RANKING_RULES.md](RANKING_RULES.md) for unchanged weights, decisions, a line-by-line explanation, and limitations. Scores are rule points, never calibrated probabilities or fabricated engagement metrics. Synthetic engagement categories are visibly labeled illustrative and unmeasured; they earn no points. The dashboard makes no network calls for its interactions and stores no feedback.

See [product scope](PRODUCT_SPEC.md), [architecture](ARCHITECTURE.md), [evaluation plan](EVAL_PLAN.md), and [learning log](LEARNING_LOG.md). This is a learning baseline, not a production-readiness claim.

## Day 1 review status

The [final engineering review](DAY1_REVIEW.md) records the original 47-test review and a follow-up with 58 passing tests and two presentation-only sort modes on 2026-10-27. Both passes ran build, typecheck, and lint. The seeded demo works, but review probes found open bugs: contraction-based opt-outs can be missed, raw IDs can collide after schema trimming, and empty ranking batches bypass clock validation. All 60 annotations remain proposed, with no measured ranking quality. These issues were documented without changing `rules-v2.0.0`; resolve them before expanding to arbitrary imported conversations. The current Day 1 implementation also contains uncommitted/untracked work. The shelved speech-synthesis question remains Review/45 and is recorded as a possible Day 3 evaluation failure rather than special-cased in the scorer.
